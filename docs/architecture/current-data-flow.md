# Current Data Flow

User -> Streamlit -> POST /api/v1/ask -> global TextToSQLAgent -> session create/replace -> last five SQLite messages -> SQLExtractor -> SQL prompt (FULL_SCHEMA, rules, five few-shots, history) -> LLMClient/OpenAI -> clean SQL -> TSQL AST single-statement/read-only policy -> one correction call on validation failure -> DatabaseConnection repeats the security decision before cursor execute/fetchall -> remove Id/*Id keys -> COLUMN_MAP translation -> empty fixed English answer OR LLM natural-response prompt containing only first five rows -> save user and assistant messages -> API HTTP 200 envelope -> Streamlit Markdown, DataFrame and SQL expander.

New session is created when session_id is absent; an unknown id is silently replaced. CLI omits session_id and therefore starts a new session for each question. Database errors are raw pymssql exceptions and normally reach the generic agent handler; QueryExecutionError branch is not reached. No provider fallback exists. Startup may compare an MD5 schema hash and run scripts/generate_column_map.py; its relative output path can create scripts/src/core/column_mapper.py. Empty results skip the answer LLM call.
